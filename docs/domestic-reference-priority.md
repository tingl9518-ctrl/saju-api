# Domestic reference 구축 — 연도 우선순위 (계획만)

**목표:** 운세위키와 **입춘 mismatch**가 나는 연도를 **어떤 순서로 `jieqi-reference.csv`(및 병합 파이프)에 반영할지** 정한다.  
(코드 변경 없음. **운영 정책은 `docs/event-driven-sparse-override.md`** — Tier1 feb4/feb5 blind QA **종료**, patch는 **이벤트·증상**만.)

---

## 1. 현재까지 확인된 mismatch 연도 (요약)

| 연도 | `jieqi-reference.csv` | 번들 vs 위키 (요지) | 비고 |
|------|----------------------|---------------------|------|
| **1995** | 행 있음 (`instantKst` 錨点) | **~7.9h outlier** — 위키 **16:19 KST** 전환 錨点 vs 번들 **익일 새벽대** KST | 입춘 **시각대 다양성** 샘플(오후). `qa:jieqi:report` outlier. |
| **1997** | 행 있음 | **정합** — 번들이 위키 **04:00 KST** 錨点과 동일 | **유일하게 수동 정합 완료**된 앵커. mismatch “수정 대상”이라기보다 **기준선**. |
| **2001** | 행 있음 | **~8.3h outlier** — 위키 **03:13 KST**~ vs 번들 **한낮대** | 전형적 **대형 outlier**(네 연도 중 \|Δ\| 최대). 골든·문서 다수. |
| **2024** | 행 있음 | **~8.0h outlier** — 위키 **17:27 KST**~ vs 번들 **익일 새벽대** | **저녁대 전환** — 1997·2001과 **연도별 시각 상이** 패턴. |

**정리:** 네 연도 모두 **문서·CSV에 “확인됨”**이다. **1997만 번들이 이미 위키에 맞고**, 나머지 세 연도는 **같은 비교 파이프에서 대형 outlier**로 잡힌다.

**그 외:** `npm run qa:jieqi:report`는 **1970–2035** 전 구간을 돌릴 수 있으나, **CSV가 비어 있는 연도**는 `missing_reference`로만 집계된다 — **아직 “위키 錨点 미확정”인 연도는 별도 조사 대기**다.

---

## 2. 어떤 연도를 먼저 reference화하면 효율이 좋은가

**효율 기준(권장):**

1. **병합 파이프라인 검증** — 한 번에 깨지지 않게 **“이미 맞는 연도”**로 smoke.  
2. **사용자·문서에서 노출된 대형 outlier** — **같은 행 수로 체감 mismatch 최대 감소**.  
3. **입춘 패턴 대표성** — 새벽·오후·저녁 등 **시각대 스펙트럼**을 빨리 커버해 이후 연도 분류에 재사용.  
4. **`qa:jieqi:report` 잔여 outlier 순** — 수치로 우선순위 자동화.

---

## 3. 왜 그 순서인가 (대표성·outlier·regression)

| 우선 근거 | 설명 |
|-----------|------|
| **1997 먼저(또는 동시 최소 검증)** | 병합 후에도 **diff≈0**이어야 함. **회귀 앵커** — “reference를 덮어써도 맞던 연도가 망가지면 파이프 실패”. |
| **2001·2024** | **\|Δ\|** 가 가장 크고, 문서·비교표에서 **교육용으로 이미 고정**됨. Hybrid 병합 **효과 검증**에 최적. |
| **1995** | **오후 입춘**으로 **2001(새벽)·2024(저녁)** 과 **다른 위키 UI 패턴** — “연도별 시각이 다름”을 **한 세트로 커버**. |
| **outlier 순 전부** | CSV를 채우면 **리포트에서 outlier 건수가 줄어드는지**가 **명확한 KPI**가 됨. |

## 4. 추천 순서 (단계)

### 1차 — **파이프 신뢰 + 체감 최대**

| 순서 | 연도 | 목적 |
|------|------|------|
| ① | **1997** | 병합·빌드 후 **여전히 exact** — 파이프 **무결성 앵커**. |
| ② | **2001** | 대형 outlier 제거 **효과 확인** (새벽형). |
| ③ | **2024** | 대형 outlier + **저녁형** 대표. |
| ④ | **1995** | **오후형** + 이후 **윤달 월주 QA**와 같은 “국내 그리드” 맥락에서 재사용 가능. |

*(실무에서는 ②③④를 병렬로 CSV 검증·출처 보강할 수 있으나, **병합 스크립트 첫 연결 시**는 ①을 반드시 포함한다.)*

### 2차 — **이벤트 + 수치 outlier (blind Tier1 아님)**

- **우선:** 실사용 mismatch · 경계 생시 fail · 골든 fail · 12절 월주 mismatch (`event-driven-sparse-override.md` T1–T4).  
- **보조:** `qa:jieqi:report`에서 **\|ref − bundle\| > T** 이고 **위키 錨点 확정**된 연·절만 CSV.  
- **하지 않음:** feb4/feb5 Tier1 queue 전수 — **10/10 rejected, patch 0**으로 proxy **폐기**.

### 3차 — **tolerance 이내 잔여**

- **300초 이내** 잔차만 남은 연도 — 위키 **창구 폭** vs **錨点 한 점** 문제일 수 있음. `note`·`confidence` 정리 후 필요 시만 수정.

## 5. 1900~2100 전체 커버 — 현실적인 전략

| 구간 | 현실적 접근 |
|------|--------------|
| **1970–2035** | **sparse event-driven** — 입춘 **전행 CSV 목표 아님** (예상 **10~16/66연**). 1~3차는 **증상·outlier**만. |
| **1969·사주연 경계** | 번들에 `BUNDLE_BAZI_YEAR_MIN = 1969` 존재 — **1969 입춘** 등 경계 연도는 **번들 스키마와 함께** 빠르게 1행 추가. |
| **2036–2100** | **번들 확장**(`build-solar-terms`·스키마·용량) **선행** 없이는 의미 없음. 로드맵 **Phase 2**. |
| **1900–1968** | **천문·만세력 원천 라이선스·표기 체계** 이슈. **자동 크롤 금지** 전제 시 **수동/OCR 배치** 또는 **공공 데이터** 확보 후 **10년 단위** 롤아웃이 현실적. |

**한 줄:**  
**“1900~2100”은 한 번에 아니라, `1970–2035` 완전 채움 → 번들 범위 확장 → 과거·미래 10년 단위**가 **유지보수 가능한 전략**이다.
