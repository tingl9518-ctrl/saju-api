# 운세위키와 다른 규칙 구간 — mismatch 규칙화 (조사 메모)

**QA 목표 전환:** 랜덤 샘플 확장은 중단하고, **위키와 달라질 수 있는 조건**만 규칙 형태로 정리한다.  
(코드·테스트 변경 없음. 근거는 저장소 내 CSV·QA 문서·골든 `known_mismatch`·엔진 동작 서술.)

---

## 1. 현재까지 발견된 mismatch 규칙 목록

### R1. 입춘(절기) 시각 — 번들 vs 운세위키 錨点

| ID | 조건 (언제 달라지나) | 현상 | 근거 |
|----|----------------------|------|------|
| **R1a** | **양력 입춘일 전후**(보통 **2월 3~5일**·연도별) 생시가 **입춘 instant 근처**일 때 | **연주·월주**(사주연·절입 월건)가 위키 그리드와 어긋날 수 있음 | `korean-month-pillar.js`는 **`bundle.json`의 `lichunUtc` / `baziyearTerms`** 와 KST 생시를 비교. 위키는 **연도별 다른 창구**(새벽·오후·저녁). |
| **R1b** | **1995** 입춘 | 위키 확정 전환 **2/4 16:19 KST**~(錨点 `instantKst`) vs 번들 **2/5 00:13 KST** 부근 — **~7.9h** | `reference/jieqi-reference.csv`, `docs/jieqi-qa-automation.md` |
| **R1c** | **1997** 입춘 | **정합**(번들이 위키 **2/4 04:00 KST** 錨点과 동일 시각) | 동일 로직·**데이터만** 수동 정합 |
| **R1d** | **2001** 입춘 | 위키 확정 **2/4 03:13 KST**~ vs 번들 **~11:28 KST** — **~8.3h** | 동상 |
| **R1e** | **2024** 입춘 | 위키 확정 **2/4 17:27 KST**~(錨点) vs 번들 **2/5 01:27 KST** 부근 — **~8.0h** | 동상 |

**규칙 문장:**  
> **생일이 입춘 경계(특히 2월 3~5일)에 걸리면**, 위키와의 일치 여부는 **`bundle.json` 입춘·절기 시각이 위키(국내 그리드)와 같은 출처인지**에 의존한다. **lunar-javascript 기본 번들**만 쓰면 **1995·2001·2024처럼 수시간 outlier**가 나올 수 있다.

### R2. **12절 절입** 시각 — 번들 vs 운세위키 (월주·연주에 영향)

월주는 **`baziyearTerms`의 `lastJieId`**(12절 순)만 본다. **입춘만** domestic이어도 **백로·한로 등**은 lunar-js이면 **같은 연도 안에서 입춘은 맞고 월주는 틀릴 수 있다.**

**운세위키 QA 확정 — 1995 사주연, 절기별 전환 (2026-05):**

| 절기 | `jieId` | 양력일 | 위키 그리드 (요지) | 위키 錨点 `instantKst` (전환) |
|------|---------|--------|-------------------|------------------------------|
| **입춘** | `lichun` / `ipchun` | 1995-02-04 | 16:19~ 을해/무인 | `1995-02-04T16:19:00+09:00` (CSV·병합 반영) |
| **백로** | `bailu` | **1995-09-08** | **11:45**까지 **갑신**, **11:46**부터 **을유** | **`1995-09-08T11:46:00+09:00`** 근처 |
| **한로** | `hanlu` | **1995-10-09** | **03:20**까지 **을유**, **03:25**부터 **병술** | **`1995-10-09T03:25:00+09:00`** 근처 (창구 03:20~03:25) |

**번들(lunar-js 잔여, 1995) 대비 요지:**

| 절기 | 번들 `instantUtc` (요약) | 번들 KST(요약) | 위키 錨点과 |
|------|--------------------------|----------------|-------------|
| 백로 | `1995-09-08T10:48:33.999Z` | **~19:48** | **~8h** 벌어짐 → 오전 생시는 **백로 전** 월주로 잡히기 쉬움 |
| 한로 | `1995-10-09T02:27:12.000Z` | **~11:27** | **~8h** 벌어짐 → **11:00**도 **한로 전(을유)** 로 잡힘 |

| ID | 조건 | 현상 | 근거 |
|----|------|------|------|
| **R2a** | 양력 생시가 **12절 중 어느 경계**에 걸림 | **월주**(필요 시 연주는 입춘)가 위키와 다를 수 있음 | **윤달·양력** 구분 없음 — **절기 instant**만 본다. |
| **R2b** | **1995 백로** | 위키 **09-08 11:46**~ **을유** vs 번들 **~19:48** 백로 → **09-08 낮**은 **을유 전(갑신월)** 가능 | 입춘-only 병합 **미반영** |
| **R2c** | **1995 한로** | 위키 **10-09 03:25**~ **병술** vs 번들 **~11:27** 한로 | `lunar-leap-1995-0815-1100`: 양력 **10-09 11:00** → 엔진 **을유**, 위키 **병술** |
| **R2d** | **입춘만 domestic 병합** | **1995 입춘**만 CSV 반영, **백로·한로 등 11절**은 시드 | **위키 100% 동일** 목표에는 **부족** — R2b·R2c 동시 존재로 **입춘-only 한계** 입증 |

**규칙 문장:**  
> **월주 mismatch의 핵심은 윤달·엔진 로직보다 `bundle.json`의 12절 시각(출처) 차이**일 가능성이 **매우 크다**. **입춘·백로·한로** 모두 위키에서 **실제 절입 근처 월주 전환**이 확인되었으므로, **입춘-only patch만으로는 운세위키와 전 구간 일치가 어렵다**는 판단이 타당하다.

**`known_mismatch` (`lunar-leap-1995-0815-1100`):**  
입력은 **윤달**이나, **한로(및 그 이전 백로) reference**가 번들과 다르면 **동일 증상**. **한로+백로** 錨点 반영이 필요.

### R3. 야자시(子) — **23:30** 子 시작 · 위키 **적용(당일) / 미적용(다음날)** 토글

**운세위키 QA 확정 (2026-05):**

- **子 시각:** **23:30 KST**부터 子 (본 엔진 한국형 시진과 **동일**).
- **「야자시 적용 (당일)」:** 23:30 이후에도 **양력 당일 일주** 유지.  
  *관측:* 양력 **2001-01-01 23:30** → 일주 **갑자**.
- **「야자시 미적용 (다음날)」:** **23:30부터** 일주를 **익일 양력** 기준으로 본다.  
  *관측:* 동일 시각 **2001-01-01 23:30** → 일주 **을축**.

| ID | 조건 | 엔진 (현재) | 위키 |
|----|------|-------------|------|
| **R3a** | **일주** | **양력 자정(00:00)** 에서 바뀌는 **달력 일자**로 `calculateFourPillars` — **23:30에도 날짜 안 바꿈** | **적용(당일)** 과 **일주 귀속 동일**. **미적용(다음날)** 과는 **일주 불일치** |
| **R3b** | **시지** | **23:30~익일 01:29 = 子** | 위키와 **子 시작 시각 동일** |
| **R3c** | **시천간** | **(자정 기준) 당일 일간** + 五鼠遁 | **미적용** 시 **익일 일간** 기준이 될 수 있음 — 엔진은 미구현 |
| **R3d** | 예: **2001-01-01 23:40** | 엔진: 당일 일주 유지 → **적용(당일)** 쪽과 정렬. 골든 `midnight-zishi-2001-0101-2340` 의 `expected` 는 **미적용** QA 기둥 → **`known_mismatch`** 유지 이유는 **토글 불일치** | 위키는 토글에 따라 갑자/을축 등으로 갈림 |

**규칙 문장:**  
> **양력 23:30~23:59** 및 **子 구간 전체**에서, 위키와의 일치 여부는 **「야자시 적용(당일) vs 미적용(다음날)」** 중 **어느 모드를 기준으로 삼느냐**에 달린다. 현재 엔진은 **적용(당일)과 같은 일주 귀속**이다. **미적용**을 기대하면 일주·시천간이 달라질 수 있다.  
> 문서화된 예: **2001-01-01 23:40** (`midnight-zishi-2001-0101-2340`, `known_mismatch` — 기대는 **미적용** 측).

**참고:** 옛 문서·타 서비스는 **23:00** 을 자 경계로 말하는 경우가 있다. **운세위키 본 QA 기준은 23:30**으로 고정한다.

## 2. 공통 패턴

| 패턴 | 설명 |
|------|------|
| **P1. 데이터 출처 단일화** | 위키와의 차이가 **“같은 공식 다른 입력”**으로 설명되는 경우가 많다 — 특히 **절입 JSON**. |
| **P2. 경계에서만 폭발** | 평범한 양력·낮 시간은 대체로 정합; **입춘·자시·윤달→양력 후 절기**처럼 **경계**에서만 mismatch가 드러난다. |
| **P3. 위키는 이원 토글** | **야자시** — **子 23:30** 은 엔진과 같고, **일주**만 **적용(당일) / 미적용(다음날)** 으로 갈린다. 엔진은 현재 **적용(당일)** 과 같은 일주 귀속이다. |
| **P4. Hybrid 병합 범위** | **입춘만** CSV 덮어쓰기 → **한로·백로 등**은 여전히 lunar-js. **같은 사주연(1995)** 안에서도 **입춘은 위키 정합·다른 절은 outlier**가 공존할 수 있음. |
| **P5. “윤달” 라벨 오해** | 골든 id·category는 `lunar_leap`이나, **월주 차이는 절입 시각**으로 설명 가능한 경우가 많음 (R2b). |

## 3. 아직 미확정인 영역

| 영역 | 미확정 내용 |

| **조자 00:00~01:29** | 일주는 **전날 자정 기준**인지·**당일 자시**로 묶는지 위키 **미적용** 정의와 **문자열 비교** 필요. |
| **12절 전수** | **입춘 4연도**만 CSV·병합. **1995 백로·한로**는 위키 錨点 **확정**, 번들 diff **정량 미리포트**는 미구현. |
| **나머지 9절** | 경칩·청명·…·소한 — **1995 외 연도·절** 표본 거의 없음. |
| **윤달 × 절기** | R2c가 **한로**로 설명; **윤달 특유 규칙**은 아직 **반증 없음**. |
| **위키 UI = 천문 시각?** | 그리드가 **진동시**인지 **정오**인지 **창구**인지 — 錨点 선택 시 **오차 허용** 문서화 수준. |

## 4. 12절 domestic reference — 필요성 (현재 판단)

| 근거 | 내용 |
|------|------|
| **입춘-only 성공** | 1995·1997·2001·2024 **입춘** — `qa:jieqi:report` **exact** (병합 후). |
| **동일 연도(1995) 절기 mismatch** | **백로**(09-08 11:46), **한로**(10-09 03:25) — 위키 **월주 전환** 확인; 번들은 **lunar-js**로 **수 시간** 어긋남. |
| **결론** | **월주·위키 정합** 목표 시 **12절 reference(최소 문제 절기부터)** 가 **점점 유력한 필수 경로**. **입춘-only로 위키 100% 동일은 어렵다**고 보는 것이 타당. |

| 접근 | 판단 |
|------|------|
| **입춘만 Hybrid (현재)** | **2월·연주**에는 충분. **9~10월 월주·윤달 골든**에는 **불충분**. |
| **12절 단계 확장 (권장 중기)** | **1995: 백로+한로** → 골든·윤달 케이스 검증 → **연도·절 확대** 또는 **KASI 일괄**. |
| **12절 전량** | 이상적 SoT; 운영 **~792행**(66년×12) 수준 — **리포트·병합 스크립트** 확장 전제. |

## 5. 입춘만 patch vs 12절 domestic — 비교

| | 입춘-only | 12절 domestic |
|---|-----------|----------------|
| **위키 100% (월주)** | **어려움** (R2b·R2c 입증) | **가능성 높음** (절기별 錨点 채움 시) |

## 6. 남은 리스크·QA 범위 (재평가)

| 구분 | 상태 | 비고 |
|------|------|------|
| **입춘 (1970–2035)** | **sparse 4연** CSV·exact | 1995·1997·2001·2024; **Tier1 blind QA 종료** — 이벤트·제보만 |
| **1995 백로·한로** | **위키 錨点 확정**, CSV·병합 **없음** | 번들 diff **수 시간** 추정 |
| **1995 나머지 9절** | **미조사** | 입동·대설 등 — **동일 패턴 가정만**, 미검증 |
| **다른 연도 12절** | **미조사** | 2001·2024는 **입춘만** outlier 이력 |
| **야자시** | **정책 확정**, 엔진 **적용(당일)** | `known_mismatch` 1건 — **절기와 별도** |
| **윤달 특수 규칙** | **반증 없음** | R2c로 **절기**로 설명 가능 |

**QA 범위 확장 방향:** “입춘-only mismatch” 중심 → **“12절 × 연도 reference gap”** 중심. 우선 **확정 錨点 3절(1995 입춘·백로·한로)** 을 CSV·diff에 넣고, **병합 스크립트 12절 확장**은 **설계·구현 후순위**.
