# 절입 mismatch의 성격 (입춘·12절·월주) — 현재 단계 판단

> 파일명은 `lichun-mismatch-nature.md` 이지만, **2026-05 윤달·한로 QA** 이후 범위는 **입춘뿐 아니라 12절 전체**의 domestic reference 차이를 포함한다.

연·월(사주연·절입)은 **`korean-month-pillar.js`가 `bundle.json`의 입춘·12절 시각**과 생시를 비교해 결정한다.  
아래는 **입춘(1995·1997·2001·2024)** 및 **한로(1995-10-09)** QA를 포함해, mismatch가 **엔진 버그인지 / lunar-javascript 특성인지 / domestic reference 차이인지**에 대한 **문서상 판단**이다. (코드 변경 없음.)

---

## 최종 판단 (한 줄)

**절입(입춘·한로 등) mismatch는 “계산 엔진 로직 버그”나 “윤달 특수 규칙”이라기보다, `bundle.json` 절기 시각의 **데이터 출처**(lunar-javascript vs 국내·운세위키) **차이**로 보는 것이 타당하다. 입춘만 domestic으로 맞춰도 **다른 절은 그대로 어긋날 수 있다.**

---

## 1. 연도별: 맞는 경우 vs 7시간대 어긋남 — 이유 추정

| 연도 | 운세위키 대비 | 추정 |
|------|----------------|------|
| **1997** | **정합** (번들 입춘을 위키 錨点에 맞춘 상태) | 동일 로직·동일 파이프라인인데 **번들의 `lichunUtc` / `baziyearTerms` 만 위키에 맞춤** → 문제는 로직이 아니라 **그 연도의 절입 값**이었음을 시사. |
| **1995** | **대략 7시간대 outlier** (위키 오후 창구 vs 번들이 자정 넘어 KST로 잡히는 패턴) | **lunar-javascript → 번들**이 만든 입춘 시각이 **국내 위키 그리드**와 다른 **연도별 오프셋**을 보임. 위키는 연도마다 창구 시각이 다름(오후·새벽·저녁). |
| **2001** | **약 7.5h** (위키 새벽 vs 번들 한낮대 KST) | 1997과 “같은 로직인데 틀린 결과”가 아니라, **번들 데이터가 위키와 다른 체계**로 박혀 있음. |
| **2024** | **약 7.45h** (위키 저녁 vs 번들 익일 새벽대 KST) | 2001과 **비슷한 규모**의 괴리 → **연도별 버그**보다 **단일 번들 생성 파이프(lunar-js) vs 국내 표**의 **체계적 차이**에 가깝다. |

**정리:**  
- **맞는 연도(1997):** 데이터를 위키에 맞게 맞춘 결과.  
- **7시간 이상 어긋나는 연도(1995·2001·2024):** **같은 비교식**(위키 錨点 vs 번들 UTC)에서 **번들 쪽 절입 시각**이 위키와 크게 벌어짐. **엔진이 연도마다 다른 공식을 쓰는 것**이 아니라, **입력 번들 값**이 연도마다 위키와의 거리가 다를 뿐이다.

---

## 2. 엔진 교체 vs domestic reference bundle — 현실적인 쪽

| 접근 | 판단 |
|------|------|
| **엔진(`manseryeok` 등) 전면 교체** | 입춘 mismatch의 **직접 원인**이 “일간·시진 라이브러리”에 있는 것으로 보이지 않음. 교체해도 **절입 시각을 무엇에 둘지**가 같으면 **동일 문제 재발**. **현 단계에서는 비현실적·비효율**에 가깝다. |
| **domestic reference bundle 유지·강화** | 월주·사주연은 이미 **번들 기반**이다. **입춘·12절을 국내 reference로 채운 번들**을 쓰면 같은 엔진으로 **위키 체감에 가깝게** 맞출 수 있다. **현실적인 주력**이다 (`docs/jieqi-strategy.md`, `docs/jieqi-data-pipeline.md`와 동일 결론). |

---

## 3. QA 결과 기준 — “엔진 자체는 usable”인가

**가능하다.** 조건을 붙이면 다음과 같다.

- **연·월·일·시 계산 파이프라인**(절입 테이블 조회, 시진, 음력→양력, 골든 대부분 일치)은 **일관되게 동작**하고 있다.  
- **입춘 경계에서의 “틀림”**은 재현 시 **번들 시각 vs 위키**로 설명되는 경우가 많고, **같은 입력에 대해 코드가 들쭉날쭉한다**는 류의 증거는 약하다.  
- 따라서 **“로직은 usable, 절입 데이터는 domestic 정합이 필요”**로 보는 것이 QA 요약과 모순되지 않는다 (`docs/qa-summary-milestone.md`).

---

## 4. 프로젝트 상태 한 줄

**엔진은 usable, 남은 건 domestic reference(12절·번들) 정합과 야자시 등 정책 확정.**

## 5. 12절 월주 mismatch (1995 백로·한로·윤달 골든) — 본 문서(입춘)와의 관계

### 운세위키 QA 확정 — 1995, 절기별 (2026-05)

| 절기 | 양력 | 위키 전환 (요지) | 錨点 `instantKst` |
|------|------|------------------|-------------------|
| **백로** | **1995-09-08** | **11:45**까지 **갑신**, **11:46**부터 **을유** | **`1995-09-08T11:46:00+09:00`** |
| **한로** | **1995-10-09** | **03:20**까지 **을유**, **03:25**부터 **병술** | **`1995-10-09T03:25:00+09:00`** (창구 03:20~03:25) |

### 골든 `lunar-leap-1995-0815-1100` (한로)

| 항목 | 값 |
|------|-----|
| **입력** | 음력 윤8/15 11:00 → 양력 **1995-10-09 11:00 KST** |
| **위키 월주** | **병술** (한로 이후) |
| **엔진 월주** | **을유** (번들 한로 **~11:27 KST** → 11:00은 **한로 전**) |

### 번들 대비 (입춘만 domestic)

| 절기 | 번들 (lunar-js) KST 요약 | 위키 錨点 | 비고 |
|------|--------------------------|-----------|------|
| **백로** | **~19:48** (`1995-09-08T10:48:33.999Z`) | **11:46** | **~8h** — 9월 낮은 **을유 전** 월주 |
| **한로** | **~11:27** | **03:25** | **~8h** — R2c·골든 mismatch |

**입춘(1995)** 은 CSV·병합 **정합** — **같은 연도에서 입춘만 맞고 백로·한로는 틀림** → **입춘-only로 월주 전구간 정합 불가** 입증.

### 본 문서 §1–§3과의 관계

| 구분 | 입춘 (§1) | 백로·한로 (§5) |
|------|-----------|----------------|
| **증상** | 2월 연·월주 | **9~10월 월주** |
| **원인** | `lichun` instant | **`bailu`·`hanlu` instant** |
| **입춘-only** | **개선** | **미개선** |
| **성격** | **동일 — 절기 reference(번들) 차이** |

**한 줄:** **입춘·백로·한로** 모두 위키에서 **절입 근처 월주 전환**이 확인됨. **월주 mismatch 핵심은 12절 bundle reference** 가능성이 **매우 크다**. **윤달·입춘-only patch 한계**와 **12절 domestic 전략** — `docs/wiki-divergence-rules.md` R2·§4.

## 6. 입춘만 patch vs 12절 domestic reference — 현재 판단

| | **입춘만 Hybrid 병합 (현재 구현)** | **12절 domestic reference (목표)** |
|---|-----------------------------------|-------------------------------------|
| **범위** | `merge-jieqi-reference-lichun.mjs` — CSV 행 있는 **입춘 1점/연** | `baziyearTerms[y]` **12절 전부** 또는 절기별 CSV |
| **효과** | 입춘·사주연 경계, **2월 전후 월주** | **한로·백로·…** 포함 **모든 절입 월주** |
| **골든·월주 해소** | **불가** (백로·한로 미반영) | **가능** (1995 **bailu+hanlu** 錨点 병합 시) |
| **비용** | CSV **~66행**(MVP 입춘) | **~66×12절** 또는 외부 표 일괄 |
| **판단** | **1단계로 유지·가치 있음** | **월주·위키 정합**을 목표로 하면 **필수 단계** |

**권장 순서:** 입춘 CSV·병합 **유지** → **1995 백로·한로** CSV·diff → 골든 재검증 → 장기 **12절 리포트/CI**.
